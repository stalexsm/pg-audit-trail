# ADR-0006: Единое рекурсивное маскирование образов и контекста одним словарём в точке выдачи

Все точки выдачи журнала — список `GET /api/changes` и детальная строка `GET /api/changes/{id}` — маскируют значения по одному словарю чувствительных ключей (`password`, `passwd`, `pwd`, `token`, `secret`, `api_key`; сравнение ключей точное) рекурсивно: объекты и массивы на любой глубине. Маскируются образы «до/после» (в детальной строке — полные, в списке — краткая сводка `{key, before, after}`: чувствительное имя колонки в `key` скрывает значения обоих образов целиком) и контекст приложения. Контекст маскируется наравне с образами: чтение API анонимно (ADR-0005), а payload MESSAGE — произвольный JSON клиента, где регулярно оказываются токены сессий, ключи и персональные данные; утечка через контекст опасна так же, как через образы, поэтому закрывать только образы — не закрывать ничего. Маскирование — свойство точки выдачи, а не хранения: в `changes` лежат полные значения (журнал — аудит), фильтры вхождения в `context` работают по сохранённым данным. Словарь и рекурсивная функция — одна именованная константа и одна функция в `crates/api/src/dto.rs`; обе точки выдачи пропускают через них свои JSON-поля, поэтому совпадение результата для одной записи гарантировано по построению. Решение владельца (тикет #39).

## Considered Options

- **Контекст не маскировать (маскировать только образы)** — отклонено: контекст клиент пишет свободно и несёт те же секреты, что и образы (сессии, заголовки, персональные данные); при анонимном чтении API (ADR-0005) открытый контекст — та же утечка в обход любого маскирования образов.
- **Ограничиться верхним уровнем (прежнее поведение)** — отклонено: типовые payload'ы вложены (`{"user": {"token": ...}}`), маскирование верхнего уровня по словарю из одного ключа скрывало малую долю значений; расширенный словарь без рекурсии тикет не закрывает.
- **Разные словари/точки маскирования для списка и детали** — отклонено: одна запись в списке и в детали обязана показывать одинаково скрытые значения, иначе сверка «список → деталь» ломается; одна функция и один словарь дают совпадение по построению.
- **Единый рекурсивный словарь для образов и контекста в точке выдачи** — принято.

## Consequences

- Список и деталь дают одинаковый результат маскирования для одной записи: оба DTO сериализуют образы, их сводку и контекст через одну функцию и один словарь.
- Чувствительные значения не видны в образах (включая краткую сводку списка) и контексте на любой глубине; сами имена ключей (`password` и др.) в ответе остаются — скрываются только значения.
- В БД хранятся полные значения: аудит не портится; фильтр `?user.token=...` найдёт строку по сохранённому значению, но в ответе это значение будет замаскировано.
- Словарь точный: `tokens`, `password_hint` и прочие над-/подстроки не маскируются; расширение словаря — правка одной константы в `crates/api/src/dto.rs`.
- Контекст с полем `key`, содержащим чувствительное имя, и полями `before`/`after` замаскируется как сводка образов — редкий перебор в пользу безопасности.
- Существующие строки журнала маскируются на выдаче без миграции данных; хранимые образы и контекст не меняются.
