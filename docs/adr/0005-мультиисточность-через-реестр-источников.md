# ADR-0005: Мультиисточность через реестр источников в БД аудита с REST-управлением

Журнал читает несколько источников (клиентских БД). Каждый источник — строка реестра в БД аудита, управляемая REST API без аутентификации (риск принят сознательно, наравне с остальным API). Один процесс `worker-cdc` держит задачу на источник: свой слот `waltrail_<имя>`, публикация `audit_<имя>`, свой чекпоинт, параллельная батчевая вставка в `changes`; новые и удаляемые источники подхватываются периодическим опросом реестра без перезапуска. В клиентскую БД ходит только воркер: бутстрап (публикация+слот) при подхвате источника, дроп слота при его удалении (DELETE асинхронный — API помечает, отвечает `202`, воркер исполняет). Строки журнала помечаются ключом источника, включённым в уникальные констрейнты. `SOURCE_DATABASE_URL` и глобальные `CDC_SLOT`/`CDC_PUBLICATION` удаляются — реестр единственный источник правды. Решение владельца (обсуждение мультиисточности, 3 раунда интервью).

## Considered Options

- **Статический конфиг (env/файл)** — отклонено: нет self-service добавления БД через API — того, ради чего решение затевается.
- **REST-валидация подключения при POST** — отклонено: API стал бы ходить в клиентские БД (синхронный коннект тормозит ручку); ошибки подключения видны в статусе источника в реестре.
- **Мягкое удаление / пауза источника (`enabled`)** — отклонено: брошенный слот бесконечно копит WAL у клиента (ADR-0001), промежуточные состояния воспроизводят ту же ловушку под другим именем.
- **Отдельный процесс воркера на источник** — отклонено: сложнее деплой и раздача источников; изоляция задач внутри процесса достаточна, таблица журнала одна, батчи источников не пересекаются.
- **Env-сид при пустом реестре** — отклонено: два механизма конфигурации неизбежно расходятся; миграция существующих установок — runbook в README.

## Consequences

- **CRUD источников без аутентификации**: любой, кто достучался до API, читает URL с паролями и регистрирует подключения к произвольным хостам (SSRF/эксфильтрация); риск отложен до появления аутентификации, не забыт.
- **Удаление с недоступным клиентом застревает в статусе**: воркер повторяет дроп, WAL у клиента растёт до успеха; состояние видно через `GET /sources`.
- **URL источника неизменяем** (PATCH только `ignore_tables`/`batch_size`/`message_prefix`): смена сервера = удалить и создать заново, слот старого сервера не переезжает.
- **LSN/txid разных серверов коллидируют**: уникальные констрейнты `changes` обязаны включать ключ источника, иначе вставка второго источника падает.
- **ADR-0001 не пересматривается**: транспорт тот же (pgoutput); мультиисточность размножает воркеры, а не меняет транспорт.
- Имя источника валидируется правилом имён слотов `[a-z0-9_]`, слот/публикация деривируются от него.
- Существующие установки переезжают по runbook в README: перерегистрация источника, дроп старого слота `waltrail` у клиента.
