# Журнал аудита (Waltrail)

Self-hosted журнал аудита для PostgreSQL: собирает изменения данных в единый журнал с доступом через REST API.

## Language

### Сущности журнала

**Изменение** (change):
Запись об изменении одной строки в базе клиента: где (база, схема, таблица), какая операция, образы «до» и «после», когда.
_Avoid_: событие (MESSAGE не создаёт записей журнала — это канал контекста, ADR-0004), лог-запись.

**Контекст приложения**:
Сведения о том, кто и в каком запросе произвёл изменение, передаваемые клиентом вместе с ним; хранятся в `context` строки изменения (payload MESSAGE обогащает им все строки своей транзакции).
_Avoid_: метаданные.

**trace_id**:
Идентификатор сквозной операции в клиенте, связывающий изменения строк одной операции. Waltrail не интерпретирует значение.
_Avoid_: request_id (унаследованное имя), ид запроса.

### Клиентская сторона

**Клиент**:
Приложение, чья база PostgreSQL подключена к журналу и которое передаёт контекст операций.
_Avoid_: пользователь, заказчик, consumer.

**Источник** (source):
Зарегистрированное подключение к базе клиента, из которого журнал читает изменения. У журнала может быть несколько источников; каждый узнаётся по имени и читается независимо от остальных.
_Avoid_: подключение (расплывчато), коннектор (унаследованное слово Debezium), база (база у клиента, источник — у журнала).

**Реестр источников**:
Перечень источников журнала, управляемый через REST API: регистрация, изменение, удаление. Воркер подхватывает источники из реестра без перезапуска.

**Канал контекста**:
Единственный способ передачи контекста: `pg_logical_emit_message` в собственной транзакции клиента. MESSAGE строк журнала не создаёт — обогащает `context` и `trace_id` строк своей транзакции (ADR-0004).
_Avoid_: enrichment (унаследованное слово), HTTP-канал (не строится), событие приложения (журналом не является).

### Доставка

**Дедупликация**:
Свойство журнала: изменение, доставленное повторно, сохраняется один раз.
_Avoid_: идемпотентность (механизм, а не требование).

**Чекпоинт**:
Координата в потоке изменений, до которой журнал гарантированно сохранён; точка возобновления после сбоя.
_Avoid_: offset, позиция (последняя занята координатой события в WAL).

**TOAST-колонка без изменений** (unchanged-toast):
Крупное значение, которое UPDATE не менял: PostgreSQL не пересылает его в потоке репликации, и колонки нет в образе «после» (и в образе «до») — не NULL, а именно отсутствие колонки. Waltrail не дочитывает значение из базы источника: образ остаётся без этой колонки. Если неизменённое TOAST-значение входит в ключ строки (identity-колонка), ключ собирается неполным по каталогу отношений либо строка остаётся без ключа: потерю ключа на таких строках осознанно принимаем — дочитывание относится к отдельной задаче, а ключ из TOAST-значений сам по себе антипаттерн (ключи должны быть компактными).
_Avoid_: потерянная колонка (колонка не потеряна — её и не должно быть в образе: сервер её не прислал), NULL (это не NULL).
